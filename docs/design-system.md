# Дизайн-система NST Almanac

Единый визуальный язык киберспортивного альманаха сообщества **NEKKETSU SPORTS TOURNAMENTS** (2015–2026).
Документ описывает канонические токены, типографику, компоненты и идентичность каждой страницы.
Цель: любая новая страница узнаваемо принадлежит семье, но имеет собственное лицо.

---

## 1. Философия

- **Ретро-семья:** тёмно-синяя палитра в духе 8-bit Famicom, шрифт заголовков Russo One, чистые плоские поверхности без размытых свечений текста.
- **Когезия + уникальность:** общие токены и компоненты (`--nes-*`, `.clean-card`, `.filter-btn`, `.modal-box`) наследуются всеми страницами; каждая страница добавляет свой сигнатурный элемент (soccer — турнирные сетки и рейтинг, quotes — сетка цитат с аватарами, players — боевые карточки).
- **Данные важнее декора:** структурные элементы (бейджи, сегменты рекорда, точки формы) кодируют реальную статистику, а не украшают.
- **Читаемость прежде всего:** контрастный текст, ясная иерархия, предсказуемые состояния наведения/фокуса.

## 3. Типографика

Три роли (Google Fonts, подключаются в `<head>` каждой страницы):

| Роль | Шрифт | Применение |
|---|---|---|
| `--font-title` | **Russo One** | заголовки h1/h2, ники игроков, крупные акценты |
| `--font-body` | **Rubik** (400–900, ital) | основной текст, описания, кнопки |
| `--font-mono` | **JetBrains Mono** (400–800) | цифры, статистика, eyebrow-метки, бейджи |

Иерархия: h1 `clamp(30px, 5vw, 52px)`; eyebrow 11px с letter-spacing .28em; данные карточки 11–13px; герой-винрейт 42px (800).

## 4. Глобальные примитивы

- **Сброс:** `* { box-sizing: border-box; margin: 0; padding: 0; }`
- **Запрет свечений текста:** `text-shadow: none !important;` —_family-правило против размытых ореолов._ Страница players использует gradient-text через `background-clip` (без text-shadow).
- **Скроллбар:** кастомный, в палитре. Family: 8px, трек `#050d18`, thumb `#234568`, hover `#38bdf8`. Players: 11px, трек `--surface`, thumb `--line`, hover `--cyan`.
- **Фокус:** `:focus-visible { outline: 2px solid var(--cyan); outline-offset: 2px; }`
- **Reduced motion:** `@media (prefers-reduced-motion: reduce)` отключает анимации появления/ховера/модалки.

## 5. Компоненты

### Общие (soccer.css)
- `.clean-card` — базовая карточка поверхности; `.cards-grid` — адаптивная сетка.
- `.filter-btn` (+ `.active`, `.inactive-tab`) — фильтры/табы; активный залочен gold.
- `.league-badge` — бейдж лиги (Высшая/Средняя/Дворовая).
- `.res-win / .res-loss / .res-draw` — исход матча.
- `.modal-box` — модальная анкета.

### Players (боевая карточка)
- `.pcard` — карточка с цветной кромкой статуса (`--edge`), срезанным углом «картриджа» и CRT-строкой; ховер = подъём + свечение кромки.
- `.rating` + `.wr` — герой: винрейт как «боевой рейтинг».
- `.recbar` — сегментированный рекорд В-Н-П (пропорционально матчам): зелёный/серый/красный.
- `.formrow` + `.dot` — пиксельные точки формы (последние 5 матчей, свежий справа; недостающие слоты пустые).
- `.dchip` — иконка дисциплины + число матчей.
- `.elo` / `.league` — футбольные экстры, рисуются только при наличии.
- `.dossier-scrim` / `.dossier-modal` — досье: карьера, «где играет», главный соперник (H2H), цитата, кнопка перехода в дисциплину.

## 6. Идентичность страниц

| Страница | Файл | `data-discipline` | Сигнатурный элемент |
|---|---|---|---|
| Хаб | `index.html` ← `landing_page.html` | `hub` | флагманские карточки разделов (`.flagship-card`, кромка green/gold), японские подзаголовки (`熱血`), gold-навигация |
| Футбольная лига | `soccer.html` ← `soccer_page.html` | `soccer` | 7 табов (Рейтинг, Карточки игроков, Сезоны 1–9, Клубные 2х2, Спецтурниры, Личные встречи, Зал славы), таблицы и сетки, deep-link `#/player/<ник>` |
| Альманах цитат | `quotes.html` ← `quotes_page.html` | `quotes` | `.random-hero` «Случайный перл комьюнити», сетка цитат с аватарами, поиск и фильтр по автору |
| Каталог игроков | `players.html` ← `players_page.html` | `players` | боевые карточки, сегментированный рекорд, точки формы, досье с переходом в дисциплину |

Все страницы: тёмно-синий фон, Russo One заголовки, общие акценты. Каждая уникальна раскладкой и сигнатурным элементом.

**Правило новой страницы:** свой `data-discipline`, свой шаблон в `templates/`, свой CSS-файл с токенами семьи, свой сигнатурный элемент. Не копировать чужую раскладку целиком.

## 7. Аудио-дека (общая)

- `audio-player.js` + `audio-player.css` подключаются на каждой странице; `audio/playlist-manifest.js` — манифест плейлистов.
- Плейлисты: `hub` (🏛️ ХАБ), `soccer` (⚽ ФУТБОЛ), `quotes` (📜 ЦИТАТНИК), `hockey` (🏒 ХОККЕЙ), `basketball` (🏀 БАСКЕТБОЛ), `fighting` (🥊 ДРАКИ 2x2).
- `detectDiscipline()` читает `body[data-discipline]`; если значения нет в манифесте — разбирает URL, иначе `hub`. **`players` в манифесте нет → каталог играет hub-плейлист** (сознательно: страница общая).
- Дека `#nekketsu-audio-deck`: `position: fixed; bottom: 0; height: var(--audio-bar-height) = 52px; z-index: 99999`; плейлист-поповер `100000`.
- `audio-player.css` задаёт `body { padding-bottom: 52px !important; }` — контент не перекрывается декой. Страницам не нужно дублировать этот отступ.
- **Слои:** модалка страницы должна быть выше деки, иначе дека отрисуется поверх затемнения и перекроет низ модалки. Каталог: `.dossier-scrim { z-index: 100001 }`.

## 8. Адаптивность

- Сетки: `repeat(auto-fill, minmax(258px, 1fr))` (players), аналогичные auto-fill на других страницах.
- Players breakpoints: `≤560px` → 2 колонки, уменьшенный герой, карьера 2×2; `≤400px` → 1 колонка.
- Шапки и панели инструментов переносятся (`flex-wrap`), поиск занимает всю строку на мобильных.

---

## 9. Доступность

- Видимый фокус (`:focus-visible`), карточки открываются по Enter/Space, Escape закрывает модалку, фокус возвращается на исходный элемент (если он ещё в DOM).
- **Контент модалки:** `role="dialog"`, `aria-modal="true"`, `aria-labelledby` на заголовок; фон (`.catalog-wrap`) получает `inert`, Tab циклится внутри модалки. Без этого клавиатура уходит в фон под затемнением.
- `aria-label` на фильтре и поиске, `role="button"` + `aria-label` на карточках.
- Контраст текста на тёмном фоне; статус передаётся не только цветом (бейдж текстом, рекорд цифрами В-Н-П, у точек формы — `title`).
- `prefers-reduced-motion` уважается: ни стаггера, ни ховер-сдвига, ни анимации модалки.
- **Анимация появления — только на первом рендере.** Перерисовка по поиску/сорту не должна заново прятать карточки (иначе строка мигает на каждом нажатии).

## 10. Данные → UI (каталог игроков)

Источник: `portal/players_dataset.py` → `{ stats, disciplines[], players[] }` (чистый архив: без demo и дублей).

- **Универсальные поля** (есть у всех): рекорд В-Н-П, винрейт, голы, статус, дисциплины, форма, турниры, соперники. Несущая карточки.
- **Футбольные экстры** (только soccer): Elo, пик Elo, лига, сухие матчи. Рисуются только при наличии — у ветеранов без Elo карточка не ломается.
- **Дисциплины:** иконки из данных; фильтр показывает дисциплины с реальными игроками, остальные — disabled «скоро». Сейчас все 105 — футбол; баскет/хоккей/доджбол — демо-сиды.
- **Навигация «насквозь»:** deep-link `<страница дисциплины>#/player/<ник>`. Сейчас готова только `soccer.html`; карта `DISCIPLINE_PAGES` в `players.js` расширяется по мере появления страниц.

## 11. Сборка и интеграция

- Шаблоны `templates/*.html` рендерятся `portal/templates.py: render(name, values)` — простая замена `@@TOKEN@@` (без HTML-экранирования; `KeyError` на маркер без значения).
- **JSON внутрь `<script>` — только через `portal/templates.py: json_for_script(value)`.** Он экранирует `<`, `>`, `&`, U+2028/U+2029: строка из сообщества с `</script>` иначе разрывает script-элемент ещё до запуска JS, и клиентский `esc()` тут не помогает. `build_players_page.py` уже использует его.
- **Долг:** `build_quotes_page.py` и футбольный билдер ещё вставляют JSON через `json.dumps` — их нужно перевести на `json_for_script` отдельной задачей.
- Клиентский JS экранирует через `esc()` **каждую** интерполяцию данных сообщества в `innerHTML` (ники, VK-имена, цитаты, статусы, названия дисциплин, иконки, соперники, URL аватаров).
- `build_all.py`: `BUILDERS` (порядок шагов), `PAGES` (`index/soccer/quotes/players`), `ASSETS` (`players.js`, `players.css`, аудио). Копирование в `deploy/`.

## 12. Конвенции и ограничения

- Русский язык обязателен в текстах интерфейса, коммитах и комментариях.
- Секреты только из `.env`/переменных окружения; `.env` не в git; `vercel.json outputDirectory "."` — всё закоммиченное отдаётся сайтом, никаких секретов/временных файлов в дереве.
- Мёртвый код не удалять — переносить в `archive/` (например, отвергнутый «выпускной альбом» → `archive/yearbook-players/`).
- `ruff check` — да; `ruff format` — не запускать.
- Спеки/планы/хендоверы и процессные документы держать вне git (served-tree гигиена).
