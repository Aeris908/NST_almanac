# Сохранение решения в очереди — 11 ноября 2026

Причина обращения: основная кнопка оставалась неактивной до отдельного предпросмотра.
Пользователь воспринимал это как поломку сохранения. На копии базы старый сценарий
«предпросмотр → сохранение» работал для обычных и командных задач.

Теперь основная кнопка активна и сначала называется «Проверить решение».
Она выполняет валидацию и предпросмотр без записи. После успешной проверки кнопка
называется «Сохранить решение», рядом явно описан следующий шаг. Только повторное
нажатие записывает решение в базу. Изменение данных снова включает шаг проверки.
При ошибке можно исправить поля и повторить действие; кнопка блокируется на время запроса.
Отдельная кнопка предпросмотра сохранена. Механизмы версий, конфликта и отмены не менялись.

Проверено в реальном браузере через изолированную копию API/SQLite: обычная задача,
смена полей после предпросмотра, предпросмотр отклонения командного отчёта, изменение
игр командного отчёта с успешным сохранением и закрытием задачи. Первая проверка
не записывает решение. 23 теста редакторских сценариев прошли. node --check queue.js — OK.
Перед публикацией сохранены исходники и согласованный снимок Neon. Тестовые вердикты
и изменения матчей выполнялись только в scratch/queue-save-test.db.
