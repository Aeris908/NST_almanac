# Сохранение решения в очереди — 11 ноября 2026

Причина обращения: основная кнопка оставалась неактивной до отдельного предпросмотра.
Пользователь воспринимал это как поломку сохранения. На копии базы старый сценарий
«предпросмотр → сохранение» работал для обычных и командных задач.

Теперь основная кнопка активна и сначала называется «Проверить решение».
Она выполняет валидацию и предпросмотр без записи. После успешной проверки кнопка
называется «Сохранить решение», рядом явно описан следующий шаг. Только повторное
нажатие записывает решение в базу. Изменение данных снова включает шаг проверки.
При ошибке можно исправить поля и повторить действие; кнопка блокируется на время запроса.
Отдельная кнопка предпросмотра сохранена. Механизмы версий, конфликта и отмены не менялись.

Проверено в реальном браузере через изолированную копию API/SQLite: обычная задача,
смена полей после предпросмотра, предпросмотр отклонения командного отчёта, изменение
игр командного отчёта с успешным сохранением и закрытием задачи. Первая проверка
не записывает решение. 23 теста редакторских сценариев прошли. node --check queue.js — OK.
Перед публикацией сохранены исходники и согласованный снимок Neon. Тестовые вердикты
и изменения матчей выполнялись только в scratch/queue-save-test.db.


## Исправление серверной записи PostgreSQL

После разблокировки кнопки пользователь сообщил ошибку `syntax error at or near "or"`.
Причина: `edit.set_place` и `edit.add_match` вызывают общие функции создания стадий
и турниров из `db/build_db.py`. Те использовали `insert or ignore`, допустимый только
в SQLite. Предпросмотр работал на SQLite-копии, а сохранение падало в Postgres.

Операторы заменены на `insert ... on conflict do nothing`, совместимый с обеими базами.
Та же замена сделана для создания дисциплины и демонстрационных турниров. Обёртка
диалекта не маскирует этот запрос: общий код теперь сразу использует переносимый SQL.

Добавлены настоящие интеграционные тесты на отдельном локальном PostgreSQL:
`tests/test_pg_review_writes.py`. Запуск: задать `NST_PG_TEST_URL` на свой тестовый сервер
localhost и выполнить `python -m pytest tests/test_pg_review_writes.py -q`.
Адрес удалённого сервера тест отвергает. На каждый тест создаётся отдельная схема с
локальной копией данных; схема удаляется в finally. Проверены запись/commit, повторное
получение существующей стадии без дублей, отмена обычного и командного решений,
откат первой игры при ошибке второй. Также проверен полный API-сценарий: предпросмотр на SQLite-копии → сохранение
в Postgres → пересчёт ответа → отмена. Все 4 проверки прошли на PostgreSQL 18.6.
Тестовых записей в Neon не делали. Сохранены исходники и согласованный бекап продовой базы.
