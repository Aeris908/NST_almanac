`pytest`, `ruff 0.17.3` (только проверка счётчиков), статичная витрина на HTML/JS +

## 2. Доступ, секреты, чего нельзя делать

- VK-токен берётся **только** из `VK_API_TOKEN` или `.env` (`portal/env_file.py: secret`).
  Пользовательский ключ, админства у сообщества нет. **Токен никогда не печатать и не
  слать в чат.**
- `.env` не должен попасть в git; в репозитории лежит только `.env.example`.
- `vercel.json` имеет `outputDirectory: "."` — всё закоммиченное отдаётся сайтом. Никаких
  секретов и временных файлов в дереве.
- Сервер правки поднимать **только** с одноразовым `NST_EDITOR_TOKEN` в окружении процесса.
- Классификатор блокирует: `vercel ls`, `npx vercel`, `taskkill //F //IM python.exe`
  (машино-широкое действие), чтение `HKCU\Environment`. **Не повторять эти попытки.**
  Локальные серверы останавливать по конкретному PID или TaskStop'ом фоновой задачи.
- Вне рабочей директории ничего не трогать (см. чужую папку в разделе 1).
- Push, force-push, теги, удаление веток — только по явной просьбе.
- Историю коммитов не переписывать («дефект признавать вслух, историю переписывать только
  по его слову»).

## 4. Модель данных (коротко, без этого правки не делать)

- `matches` — один слой на строку: `row_set ∈ {pool, catalog, special, team}`; `phase`,
  `status`, `in_rating_pool`, `manual`, `duplicate_of`, `hidden_by`, `doc_id`, `tour`,
  `league`, `is_playoff`, провенанс `source`, `source_ref`, `source_locator`, `source_page`,
  `source_text`, `note`.
- `match_sides` (2 строки на матч, `side_index` = **0/1**, не 1/2): `outcome`
  (win/loss/draw/none), `score`, `label` → `side_players` → `players`
  (`kind ∈ player|clan`) → `player_aliases` (`alias UNIQUE`, `source ∈
  name_tables|editor`, `ON DELETE CASCADE`).
- **Исход отдельно от счёта (механизм #88):** нога, сыгранная вничью по голам и решённая
  серией буллитов, хранит ничейный счёт и `outcome = win/loss` по сторонам. Валидатор
  принимает победу при равном счёте **только вне `phase='regular'`**
  (`db/validate.py`, инвариант «исход не согласован со счётом»); то же зеркалит
  `db/edit.py: phase_problem`. Писать такие исходы должен импортёр (`import_league`
  через `series_for_sides`), а не ручная правка.
- `tournaments(id, season, kind, name)` и `tournament_docs` — рамка спец- и командных
  турниров.
- `corrections` — журнал правок. **В коммитящемся состоянии база обязана иметь пустой
  (неотменённый) журнал.** Структурные исправления делаются воспроизводимо сборкой, а не
  операцией правки: правка через `db/edit.py` ставит `manual = 1` и для массовых
  изменений не годится.
- `hidden_by` прячет строку от витрины, `duplicate_of` только помечает (ничего не прячет).
- Elo (`portal/elo.py`): R0=1500, K = 24 лига / 32 плей-офф / 16 прочее, S = 1 / 0.75 (ОТ
  **или** буллиты) / 0.5 / 0.25 / 0, MOV-потолок 2.0. Строки каталога
  (`in_rating_pool = 0`) рейтинг не двигают, поэтому #88 не изменил ни одного Elo;
  смена счёта без смены победителя рейтинг тоже не двигает.
- `data/nst.db` **не** в git (игнорируется) — он regenerable. В git попадают: носители,
  `data/vk_recheck_*.md|json`, `data/sportcup_decisions.json`, `soccer.html`, `index.html`,
  `quotes.html`, `deploy/`, `nekketsu_master_table.json`, `data/headline_stats.json`.

## 7. Как проверить любую правку

```bash
python -m pytest -q                      # 299 тестов
python db/validate.py                    # 23 инварианта
python scratch/audit_final.py            # сквозной аудит (в конце печатает «ВСЁ СОШЛОСЬ»)
python scratch/verify_build.py check     # сам запускает build_all.py и сверяет 22 артефакта
```

- `pytest -q` в этой среде не печатает итоговую строку — успешность определять по коду
  выхода и счётчику `--collect-only`.
- Если вывод витрины изменился **законно**: посчитать смысловой дельт-аут
  (`db/api.diff(before, after)` — позиционный diff на пересортированных списках врёт),
  открыть страницу в браузере и проверить глазами, затем `python scratch/verify_build.py
  snapshot`. Образец смыслового промера — `scratch/delta_88.py`.
- Счётчики `ruff check <файл>` сравнивать для каждого тронутого файла отдельно с его же
  версией из HEAD: `git show HEAD:path | ruff check --stdin-filename path -`.
- Витрина локально: `python -m http.server 8099 --bind 127.0.0.1` фоновой задачей,
  дальше `mcp__browser-use__navigate_page` / `evaluate_script`.
- Скриншот работает только если встроенный браузер виден пользователю; иначе проверять
  DOM через `evaluate_script` (лимит ~15 с на скрипт).
- Промеры, которые импортируют `build_final_analytics` или `db.build_db`, обязаны сначала
  подменять секрет: `patch.setattr("portal.env_file.secret", lambda name, path=None: "")`,
  иначе уйдут в сеть.

  совпадают 18/18, т.е. данных противоречия нет — вопрос в том, снимать ли дубль. Чинить
  нельзя молча: это меняет headline (число матчей и голов), а headline — витрина владельца.

  `ALIAS_MAP`, ориентация не доказана — осталась ничьей. Лечится одной строкой в
  справочнике алиасов + пересборка.

## 10. Ловушки (все измерены, не догадки)

1. `import build_final_analytics` сам проверяет соединение с VK и грузит снапшот — любой
   промер с его импортом уходит в сеть. Для офлайн-промеров подменять секрет или читать
   JSON напрямую.
2. Позиционный diff payload врёт на пересортированных списках — только `db/api.diff`.
3. `scratch/verify_build.py check` **пересобирает сам**; «файлы изменились до пересборки» —
   не баг, а порядок шагов.
4. id строк базы меняются от сборки к сборке — ссылаться на них можно только как на «id в
   текущей сборке».
5. Пул проверять по `side_players → players.nick`, а не по `match_sides.label`: label
   хранит написание источника.
6. `git add` с одним несуществующим путём отменяет всю команду; не глушить stderr.
7. В Git Bash `$_` и русские пути в `-Command` ломаются — скрипты правки писать файлом
   (`.ps1`) с ASCII-сообщениями внутри; heredoc-питон в Bash-инструменте работает.
8. Серия буллитов **всегда с победителем**: `(4:4)` в скобках — не серия, а повтор счёта;
   `shootout_of` такие отбрасывает (без этого Сезон 1 даёт 4 ложных срабатывания).
9. Ориентация серии: искать **оба** имени в строке (алиасы + `homoglyph_fold` + границы
   слов — без границ «вор» ловится в «Дворовая» и в «BOP213»); не опознали — возвращать
   None, а не гадать. `ALIAS_MAP` неполон: «мафута» там нет — отсюда оставшаяся ничья.
10. Строка kot-from-ussr ↔ Веселый Роджер (незакрытая скобка + проза, называющая другого
    победителя) остаётся ничьей **намеренно**: противоречие источника не разрешается
    молча.
11. Инвариант «алиас не переименовывает уже заведённого игрока» и `fold_duplicate_cards`
    держат карточки от склейки гомоглифов; менять только вместе с тестом.
12. Приёмочные тесты на копии живой базы (`tests/conftest.py: db_path`) пропускаются,
    если копии нет — «тестов меньше» не значит «что-то сломалось».

## 11. Как брать задачу в работу

Один шаг — одна задача. Список дел сразу весь, параллельные субагенты только с
разделением файлов; файл, который ведёт субагент, в полёте не трогать и не пересобирать.
Каждая задача закрывается коммитом с русским сообщением по образцу существующих
(«#NN: что и почему»), после полного цикла проверки из раздела 7.
